The key lesson:

Constraints are a fingerprint of the intended algorithm.

For example:

n ≤ 20       → 2^n may be possible
n ≤ 40       → meet-in-the-middle
n ≤ 100      → O(n³) possibly
n ≤ 2,000    → O(n²) territory

n huge       → exploit structure/math

The "Unnamed Pattern" Layer
There are lots of problems that don't look like a named LeetCode pattern but repeatedly have the same internal structure.
