# Data and Messaging Services

## S3

- **S3** is object storage: you put **objects** (files, any size up to terabytes) into **buckets** under a **key** (a path-like name), and get them back by key over HTTP. It is effectively **unlimited**, designed for **eleven nines (99.999999999%) of durability** (your data is replicated across devices and AZs automatically), and since December 2020 it provides **strong read-after-write consistency** — write an object, read it immediately, and you get the new version (no more "eventually consistent" S3 surprises).
- It is the backbone of a huge range of systems: static website assets (behind CloudFront), **data lakes**, backups and logs, and — central to this series — **ML datasets and model weights** that GPU serving pulls at startup (Booklets 9–10). Its **storage classes** trade retrieval speed for cost: **Standard** (hot), **Intelligent-Tiering** (auto-moves objects by access pattern), **Infrequent Access**, and **Glacier** tiers (cheap archival, minutes-to-hours to retrieve). **Lifecycle policies** move or expire objects automatically (logs → IA after 30 days → Glacier after 90 → delete after a year).

:::warn
The **public S3 bucket** is the most famous cloud data leak, and it's pure misconfiguration (Module 1). A bucket or object made public — often by a well-meaning "just make it work" change — exposes everything in it to the entire internet, and crawlers find it fast. AWS now enables **Block Public Access** at the account and bucket level by **default**; **leave it on**, serve public assets through **CloudFront with Origin Access Control** (so the bucket itself stays private), and grant application access via **IAM roles / bucket policies scoped to specific prefixes** — never "public read." Audit with S3 Access Analyzer. Treat "is any bucket public?" as a standing security check.
:::

- Access is governed by **IAM + bucket policies** (Module 1), and you can restrict a bucket to a **VPC endpoint** (Module 2) so it's reachable only from your network. Remember the **egress** cost model (Module 6): storage is cheap; pulling lots of data **out** to the internet is where S3 bills add up — which is another reason model-serving nodes pull weights over a **gateway endpoint**, not the internet.
