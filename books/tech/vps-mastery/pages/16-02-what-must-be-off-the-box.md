## The five things that must exist elsewhere

- Recovery is only possible if all five are somewhere other than the server. Anything missing turns thirty minutes into days

| # | Item | Where | Verified by |
|---|---|---|---|
| 1 | Application code | GitHub | It is already there |
| 2 | Container images | GHCR | Tagged by commit |
| 3 | Infrastructure files | GitHub, same repository | Compose, Nginx, scripts |
| 4 | Secrets | `.env.enc` in the repository, key in a password manager | Page 11-04 |
| 5 | Data | restic repository at a **different provider** | Page 12-05 |

### The credentials needed to reach all five

- These cannot live on the server. They belong in a password manager, and at least one other person must be able to open it

```text
- GitHub account, with the repository and GHCR access
- restic repository URL, its access key, and its password
- The age private key for .env.enc
- The DNS provider login
- The VPS provider login, with billing that works
```

### The dependency loop to avoid

- Storing the password manager's recovery key in a document on the server is a loop that only reveals itself during recovery
- The same applies to two-factor codes generated by an app on a phone that is also lost, and to a recovery email address hosted on the failed machine

### Test the list, not the intention

- Once a quarter, from a laptop with nothing set up: log into the provider, pull the repository, decrypt `.env.enc`, list restic snapshots
- **If any step needs something only on the server, the plan does not work.** Finding that out on a Tuesday afternoon is free
