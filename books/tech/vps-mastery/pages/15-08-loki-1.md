## Loki and container logs

- Loki indexes **labels**, not log contents. That makes it far cheaper than a full text search engine and shapes how it is queried

```yaml
loki:
  image: grafana/loki:3.5.1
  command: -config.file=/etc/loki/config.yml
  volumes:
    - ./monitoring/loki.yml:/etc/loki/config.yml:ro
    - lokidata:/loki
  networks: [edge]
  restart: unless-stopped
```

### Getting logs in

- **Promtail is deprecated.** Grafana Alloy replaces it. The simplest route on one box is the Docker logging plugin

```bash
docker plugin install grafana/loki-docker-driver:3.5.1 --alias loki --grant-all-permissions
```

```yaml
services:
  orders:
    logging:
      driver: loki
      options:
        loki-url: "http://localhost:3100/loki/api/v1/push"
        loki-retries: "3"
        loki-batch-size: "400"
        mode: "non-blocking"
```

- **`mode: non-blocking` is not optional.** In blocking mode, a Loki outage stops the application from writing logs, which stops the application

### Label carefully

- Labels are indexed and their combinations create streams. `service` and `color` are good labels. A request ID is not
