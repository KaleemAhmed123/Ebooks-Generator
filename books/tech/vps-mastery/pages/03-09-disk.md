## Disk, and what fills it

```bash
df -h                       # free space per filesystem
df -i                       # free inodes. A separate way to run out
du -sh /var/lib/docker      # 24G
du -sh /var/lib/docker/* | sort -h    # broken down, smallest first
ncdu /                      # interactive. sudo apt install ncdu
```

### The usual suspects, in order

| Path | Cause | Fix |
|---|---|---|
| `/var/lib/docker/overlay2` | Old image layers and build cache | Page 05-05 and 17-04 |
| `/var/lib/docker/containers` | Container logs with no rotation | Page 05-05 |
| `/var/log/journal` | Journal with no size cap | `journalctl --vacuum-size=200M` |
| `/var/log/nginx` | Access logs. Rotated by default, kept 14 days | Adjust in `/etc/logrotate.d/nginx` |
| A database volume | Actual data, or a runaway table | Page 12-01 |

### Running out of inodes

- Every file consumes an inode regardless of size. Millions of tiny cache files exhaust them while `df -h` still shows free space
- The symptom is `No space left on device` on a disk that looks empty. `df -i` shows the truth

### Deleting a file does not always free space

- A file still held open by a running process keeps its blocks. `df` shows no change until the process closes it or restarts

```bash
sudo lsof +L1        # open files that have already been deleted
```
