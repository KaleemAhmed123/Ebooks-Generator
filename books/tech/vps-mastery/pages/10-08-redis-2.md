### maxmemory is not optional

- Without a limit, Redis grows until the container hits its memory cap and is killed with exit 137
- **Set `maxmemory` below the container limit**, leaving headroom. 192 MB inside a 256 MB container

| Policy | Behavior when full |
|---|---|
| `noeviction` | Writes fail. Correct for a queue or a lock store |
| `allkeys-lru` | Evicts least recently used. Correct for a cache |
| `volatile-lru` | Evicts only keys with an expiry set |

- Choosing `allkeys-lru` for something used as a session store means users get logged out under load. Choosing `noeviction` for a cache means writes start failing. The policy has to match the job

### Persistence

- `appendonly no` means a restart loses everything. Correct for a pure cache, wrong for a rate limiter that must survive a deploy
- Sessions in Redis with no persistence log everyone out on restart. Either enable `appendonly yes`, or accept it
