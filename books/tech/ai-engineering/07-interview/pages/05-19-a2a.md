## What is A2A (Agent-to-Agent), and how does it relate to MCP?

- **A2A** is a protocol for **agents to talk to other agents**, including across organisational boundaries — discovery, task delegation, and exchanging results between independent agent systems.
- The complement to MCP:
  - **MCP** connects an agent **to tools and data** (vertical: agent → capability).
  - **A2A** connects an agent **to other agents** (horizontal: agent ↔ agent).
- Core ideas in A2A: an **Agent Card** advertises what an agent can do (so others can discover it), plus a task/message model for delegating work and returning **artifacts**.
- Why it matters: as agents proliferate across teams and vendors, you need a standard for one agent to hire another without bespoke integration — the same portability argument as MCP, one level up.
- Reality check: the agent-protocol space is young and moving; treat specifics as provisional.

:::interview
What's really being tested: the clean split — MCP = agent-to-tools, A2A = agent-to-agent — plus the Agent Card discovery idea and healthy caution that the standard is still maturing.
:::
