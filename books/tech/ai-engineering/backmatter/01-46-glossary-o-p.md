## Glossary: O – P

| Term | Means | In |
|---|---|---|
| **Overfitting** | learning the training data's noise; great on train, poor on test | B1 · B2 |
| **OWASP LLM Top 10** | The community-standard list of the most critical LLM application security risks (prompt injection, insecure output handling, excessive agency, etc.) | B6 |
| **PagedAttention** | vLLM's technique storing the KV cache in fixed pages like OS virtual memory, ending cache fragmentation | B4 · B6 |
| **PAIR (Prompt Automatic Iterative Refinement)** | An automated jailbreak where an attacker LLM refines its prompt using the target's refusals as feedback | B6 |
| **parallel tool calls** | A model emitting multiple tool-use blocks in one turn, run concurrently | B5 |
| **parent-document retrieval** | Retrieving on small chunks for precision but feeding the larger parent section to the LLM for context, resolving the chunk-size tradeoff | B6 |
| **Parquet** | a compressed columnar format for large tabular data | B1 |
| **Parsing** | building a sentence's grammatical structure (constituency phrases or dependency links) | B3 |
| **Patch embedding** | a flattened image patch projected into a vector for a vision transformer | B2 |
| **patch-n-pack** | Training technique packing tokens from several different-sized images into one sequence, avoiding padding | B5 |
| **patch token** | One image patch, linearly embedded, treated as a token in a ViT's input sequence | B5 |
| **PCA** | principal component analysis; compression via the data's top eigenvectors | B1 |
