## 0-1 BFS 🟡

- **The Rule:** Standard BFS only finds the shortest path on **unweighted** graphs (where every edge costs exactly 1). For weighted graphs, you must use Dijkstra's Algorithm (O(E log V)).
- **The Exception:** If a graph has edges that cost *only* `0` or `1`, you can use a modified BFS that runs in true O(V + E) linear time.

### The Core Idea

In standard BFS, all new edges cost 1, so they are added to the *back* of the queue, ensuring the queue is perfectly monotonic (e.g., `[dist2, dist2, dist3, dist3]`).
If an edge costs `0`, traversing it does not increase the distance. Therefore, it should be processed *before* the distance 1 edges. 
To maintain the monotonicity of the queue without sorting it, we use a **Deque** (Double-Ended Queue).

- If edge cost is `0`: Push to the **front** of the deque.
- If edge cost is `1`: Push to the **back** of the deque.

### Common Application

- **Grid Obstacles:** You are navigating a grid. You can walk on empty spaces (cost 0), but you can also break walls, though you want to break as few as possible (cost 1).
- What is the minimum number of walls you must break to reach the target? This is a 0-1 BFS problem.

### Implementation Concept

```ts
// Note: JS/TS does not have a built-in Deque. 
// In an interview, you can fake it with an array using .unshift() and .push(), 
// but mention to the interviewer that .unshift() is O(N).
function zeroOneBFS(start: number, adjList: {node: number, weight: number}[][]) {
  const deque = [start];
  const dist = new Array(N).fill(Infinity);
  dist[start] = 0;

  while (deque.length > 0) {
    const u = deque.shift()!; // O(N) in JS, O(1) in a real Deque

    for (const { node: v, weight } of adjList[u]) {
      if (dist[u] + weight < dist[v]) {
        dist[v] = dist[u] + weight;
        
        if (weight === 0) {
          deque.unshift(v); // High priority, process immediately
        } else {
          deque.push(v);    // Process later
        }
      }
    }
  }
  return dist;
}
```

### The trap

- **Overcomplicating with Dijkstra:** Using a Priority Queue (Dijkstra) for a graph with only 0/1 weights is technically correct and will pass most interviews. However, Dijkstra adds an O(log V) factor for every queue operation. For massive grids (e.g., 1000 times 1000), O(E log V) might actually TLE, whereas O(E) 0-1 BFS easily passes.
