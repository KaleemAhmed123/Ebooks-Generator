## Prim's Algorithm

- While Kruskal's algorithm builds the MST by picking random edges from anywhere in the graph and stitching forests together, Prim's algorithm grows a single, continuous tree from a specific starting point.
- It is functionally identical to Dijkstra's Algorithm, with one single, massive difference.

### The Mechanics

1. Pick an arbitrary starting node. Add it to the MST.
2. Look at all edges connecting the current MST to nodes *outside* the MST.
3. Greedily pick the absolute cheapest edge.
4. Add that new node to the MST.
5. Repeat until all nodes are in the MST.

### Prim vs Dijkstra

- **Dijkstra** cares about the **Total Distance from Start**. It stores `[totalCostFromStart, node]` in the Priority Queue.
- **Prim** cares *only* about the **Cost to Connect to the Tree**. It stores `[edgeWeight, node]` in the Priority Queue.
- Dijkstra answers: "What is the cheapest way to drive from New York to LA?"
- Prim answers: "What is the cheapest way to pave roads so every city is connected?"

### Implementation Concept

```ts
function primMST(n: number, adjList: {node: number, weight: number}[][]): number {
  const visited = new Set<number>();
  const pq = new MinPriorityQueue((a, b) => a[0] - b[0]);
  
  // Start arbitrarily at node 0
  pq.push([0, 0]); // [edgeCost, node]
  let mstCost = 0;

  while (!pq.isEmpty() && visited.size < n) {
    const [cost, u] = pq.pop();

    if (visited.has(u)) continue; // Already in the MST
    
    // Add to MST
    visited.add(u);
    mstCost += cost;

    // Evaluate neighbors
    for (const { node: v, weight } of adjList[u]) {
      if (!visited.has(v)) {
        pq.push([weight, v]); // Note: We push ONLY the edge weight, not cost + weight
      }
    }
  }

  return visited.size === n ? mstCost : -1;
}
```

- **Time Complexity:** O(E log V), identical to Dijkstra.
- **When to use Prim vs Kruskal:** 
  - If the graph is **Dense** (many edges, E ≈ V²), Prim is faster (especially if implemented with a Fibonacci heap).
  - If the graph is **Sparse** (few edges), Kruskal is easier to write and very fast.
  - In an interview, Kruskal is usually preferred because Union-Find is highly versatile.
