## Trie (Prefix Tree)

- **What it is:** An N-ary tree where each node represents a single character of a string
- **The Contract:** O(L) time to insert or search for a word, where L is the length of the word (independent of how many millions of words are in the dictionary)
- **Why it works:** It acts as a **Prefix Prefix-Sharer**. If you insert "apple" and "app", they share the exact same `a -> p -> p` nodes. It perfectly maps the hierarchical nature of language

### The Structure

Unlike a Binary Tree which has `left` and `right` pointers, a Trie node has a Hash Map (or a 26-element array) of children, mapping a character to the next node. Crucially, the node itself does *not* store its character; the *edge* leading to the node implies the character.

```ts
class TrieNode {
  // Using a Map allows for any character. 
  // For lowercase English only, a new Array(26) is faster.
  children: Map<string, TrieNode> = new Map();
  isWord: boolean = false; // The termination flag
}

class Trie {
  root: TrieNode = new TrieNode();

  insert(word: string) {
    let curr = this.root;
    for (const char of word) {
      if (!curr.children.has(char)) {
        curr.children.set(char, new TrieNode());
      }
      curr = curr.children.get(char)!;
    }
    curr.isWord = true; // Mark the end of the word
  }
}
```

### The Termination Flag Bottleneck

- The most common bug when implementing a Trie is forgetting `isWord`.
- If you insert "apple", the nodes for `a-p-p-l-e` are created. 
- If you then search for "app", the traversal will successfully find the `p` node. But "app" is not a word in our dictionary, it is just a prefix.
- The `isWord` boolean at the `p` node will be `false`, correctly telling us that while the prefix exists, the word itself was never inserted.

### The Autocomplete Engine

- Tries are the foundation of autocomplete systems.
- **Problem:** Given a prefix "cat", find all words that start with "cat".
- **Execution:**
  1. Traverse down the Trie using the prefix `c -> a -> t`. (Takes O(L) time).
  2. If the prefix doesn't exist, return empty.
  3. If you reach the `t` node, execute a standard DFS (Pre-order traversal) from that node downwards, collecting every path that ends at a node where `isWord === true`.

:::interview
"Can we use a Hash Set for dictionary lookups instead of a Trie?" — Yes, and for exact word matching, a Hash Set is often faster and uses less memory. A Trie is specifically required when you need to do **Prefix Matching** (e.g., "Find all words starting with X", "Find the longest common prefix of an array of strings"). A Hash Set cannot answer prefix queries without checking every single word in the Set (O(N)).
:::
