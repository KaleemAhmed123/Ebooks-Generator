## CQRS

- **CQRS** (command query responsibility segregation): the model that accepts writes and the model read from are separate. The write side stays true to the aggregate's rules; one or more **read models** — projections shaped for a specific screen or query — are built from the events the write side emits

- The read side is eventually consistent by construction: a projection catches up to an event some time after it committed, and Fowler's own caveat is the whole trade — separate models must be "balanced against the additional complexity of having separate models." CQRS is not free; it is a trade for read shapes a single model cannot serve well
- CQRS does not require event sourcing, and event sourcing does not require CQRS, but they pair naturally: the write side's event log is exactly what a projection needs to fold

### The failure

- A UI that writes through the command side, then immediately reads through a projection to confirm the write, and shows "not found" because the projection has not caught up yet. The write succeeded; the read model just hasn't heard (Module 14, page 3 covers the general fix)
