## JSON: readable, schemaless, lossy

- JSON is text with no schema: the field names travel in every message, and any tool can read it. That is why it is the default for HTTP APIs, and why it costs bytes

- It has one number type and no binary type. RFC 8259 promises interoperability for integers only inside `[-(2^53)+1, (2^53)-1]`, because most parsers use a 64-bit float

```typescript
JSON.parse('{"id": 9007199254740993}').id;   // 9007199254740992
Number.isSafeInteger(9007199254740993);      // false
JSON.parse('{"id": "9007199254740993"}').id; // "9007199254740993", intact
```

### The failure

- A 64-bit ID sent as a JSON number. The JavaScript client rounds it, silently, to the nearest float, and the next request asks for a record that does not exist. Nothing throws
- Send 64-bit IDs as strings. Every large API that issues them (Twitter's `id_str`, Stripe's prefixed IDs) already does
