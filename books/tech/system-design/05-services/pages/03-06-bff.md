## Backend for frontend

- The Backend for Frontend (BFF) pattern, popularized by Sam Newman, is a variant of the API Gateway. Instead of one massive gateway for all clients, you build a dedicated gateway for each user experience (e.g., one for Web, one for iOS)
- The mobile app needs small payloads, compressed images, and aggressive caching. The web app needs massive data tables. If you force both through one gateway, the API becomes a bloated compromise

- The critical rule of the BFF pattern is ownership. The team that builds the Mobile UI must own the Mobile BFF. The BFF is just the backend half of their frontend feature

### The failure

- The failure mode is a "general" BFF built by a separate infrastructure team. It acts exactly like a monolithic gateway, but with a trendy name
- Another failure is duplicating core business rules (like calculating tax) across the Web BFF and the Mobile BFF. BFFs should format and orchestrate data; they must never own domain logic
