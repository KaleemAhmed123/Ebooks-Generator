## Glossary: P–R

| Term | Means | Where |
|---|---|---|
| **projection** | a consumer folding events into a table shaped for one query, rebuildable from the event log | 4 · 9-06 |
| **property graph** | nodes with labels and properties, joined by typed, directed relationships that carry properties of their own | 2 · 1-06 |
| **proposer** | the Paxos role that suggests a value | 3 · 7-09 |
| **PSP** | a payment service provider that talks to the card networks, so the design never has to | 6 · 11-01 |
| **publish/subscribe** | the producer writes to a topic and the broker copies each message into every subscription attached to it | 4 · 2-02 |
| **pull model** | readers fetch from an offset, and the broker holds the request open until data arrives | 4 · 2-03 |
| **push model** | the server sends as soon as it has something. Right when latency is the product and an occasional loss is acceptable | 5 · 12-09 |
| **QPS** | queries per second. The estimate that sizes instances, thread pools and connection limits | 1 · 5-03 |
| **QUIC** | the UDP-based transport under HTTP/3, with TLS 1.3 built in and per-stream loss recovery | 1 · 6-04 |
| **quorum commit** | requiring a majority, rather than a named follower, to acknowledge before commit, so no single machine can stall the leader | 2 · 5-05 |
| **quorum queue** | a RabbitMQ queue replicated as a Raft group, confirmed once a majority holds the message | 4 · 2-04 |
| **quota** | a bound on a long interval, set because that is what was purchased. Billing, not engineering | 5 · 10-01 |
| **range partitioning** | assigning each partition a contiguous range of sorted keys | 2 · 8-02 |
