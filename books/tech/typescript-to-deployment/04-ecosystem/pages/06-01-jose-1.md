# Module 6 - Auth and security libraries

## jose

- HTTP forgets. Every request arrives with no memory of the one before it, so something has to prove who is calling
- A session cookie proves it by storing the answer on the server and handing the browser a key to it
- That works until the thing checking the token is a different service, which would now have to call yours on every request
- A **JWT**, JSON Web Token, moves the answer into the token itself. It carries the user id and role, signed so it cannot be edited
- Any service holding the key can verify it alone, with no network call, which is why it is the default across service boundaries
- Signed does not mean secret. The payload is base64 and anyone can read it, so nothing private goes inside
- The real cost is that a signed token stays valid until it expires. You cannot un-issue it, which is why lifetimes are short
- `jose` implements JWT, JWS, JWE and JWKS against the actual specifications, including verifying against a provider's rotating public keys
- `jsonwebtoken` predates most of those specifications and has no answer for key sets
- Version 6.2.10

```bash
npm i jose
```
