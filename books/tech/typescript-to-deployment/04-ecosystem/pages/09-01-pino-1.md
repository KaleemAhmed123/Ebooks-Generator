# Module 9 - Observability

## pino

- When a request fails at 3am, the only thing that survives is what you wrote down
- `console.log` writes it, but it writes a sentence, and a sentence cannot be searched by field across ten instances
- It is also **synchronous**. Every call blocks the event loop until the write completes, which Booklet 3 covers as the thing that stalls every request
- A **structured logger** writes one JSON object per line instead of a sentence
- That single change is what makes `orderId=o1` a filter in Loki or CloudWatch rather than a grep across machines
- It also does the writing off the main thread, so logging stops competing with serving traffic
- **Log levels** let one build be quiet in production and verbose while you are debugging, without editing code
- **Redaction** matters more than it sounds. Logging a request's headers puts a live auth token in your log store, where it lives as long as the retention policy says
- pino is the fastest of the Node loggers by a wide margin, which is the entire reason it exists
- Created by Matteo Collina. Version 10.3.1

```bash
npm i pino pino-http
npm i -D pino-pretty
```

```ts
import pino from "pino"

export const logger = pino({
  level: process.env.LOG_LEVEL ?? "info",
  redact: ["req.headers.authorization", "req.headers.cookie", "*.password", "*.token"],
  formatters: { level: (label) => ({ level: label }) },
})

logger.info({ orderId, sellerId }, "order created")
```
