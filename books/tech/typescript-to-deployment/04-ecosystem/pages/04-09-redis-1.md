## Redis with ioredis

- Every read that hits the database costs a network round trip and a disk seek, even when the answer has not changed in an hour
- **Redis** is a database that keeps everything in memory, which makes a read microseconds instead of milliseconds
- Losing the data on restart is acceptable, because it is a copy of something you can rebuild
- It is single threaded, so every command runs to completion before the next one starts, and that is what makes counters and locks reliable
- It stores more than strings. Lists, sets, sorted sets, hashes and streams each remove a problem you would otherwise solve in application code
- That is why it ends up doing five jobs in most backends: cache, rate limit counter, session store, lock, and queue backing store
- The cost is that memory is expensive and finite. A key without an expiry is a leak that eventually evicts something you needed
- `ioredis` is the client most Node backends use, and the one BullMQ requires
- Redis was created by Salvatore Sanfilippo in 2009
- Version 6.0.0 of ioredis

```bash
npm i ioredis
```

```ts
import Redis from "ioredis"

const redis = new Redis(process.env.REDIS_URL, {
  maxRetriesPerRequest: null,
  enableReadyCheck: false,
})

await redis.set("seller:s1:name", "kaleem", "EX", 3600)
const name = await redis.get("seller:s1:name")
```

- `"EX", 3600` sets a one hour expiry. **A key with no expiry is a memory leak with extra steps**
