# Module 3 - Validation

## Zod

- TypeScript disappears at build time, so nothing checks a request body once the server is running
- `req.body as Order` is a claim, not a check. Booklet 1 covers why that is the trust boundary problem
- A **validation library** inspects a value at runtime and reports whether it matches an expected shape
- Most of them make you write that shape twice: once as a TypeScript type, once as a validator
- The two drift apart the first time somebody adds a field to one and forgets the other, and nothing warns you
- Zod's idea is to write only the schema, then derive the TypeScript type from it
- One definition means drift is not possible, because the type is generated from the thing doing the checking
- The same schema also validates queue messages, webhook payloads and environment variables, not only HTTP bodies
- The cost is that schemas are real values that exist at runtime, so they add weight a plain type does not
- Created by Colin McDonnell, first released in 2020
- Version 4.5.4

```bash
npm i zod
```

```ts
import { z } from "zod"

const Order = z.object({
  id: z.string(),
  sellerId: z.string(),
  total: z.number().int().positive(),
  note: z.string().optional(),
})

type Order = z.infer<typeof Order>
// { id: string; sellerId: string; total: number; note?: string }
```
