## Glossary: M

| Term | Means | # |
|---|---|---|
| **memory, episodic** | what happened in past sessions. Retrieved, not carried | 7 |
| **memory, procedural** | how to do the job: instructions, tools, examples. Changes by review | 7 |
| **memory, semantic** | durable facts about a user. A row in a table, not a vector | 7 |
| **memory, working** | the current message array. Bounded by the **context window** | 7 |
| **memory tool** | file operations a model requests and your application executes | 7 |
| **Meilisearch** | a search engine with typo tolerance out of the box | 4, 8 |
| **microtask** | a promise callback. Runs before the next macrotask, and can starve the loop | 3 |
| **middleware** | a function in a request pipeline that can act before or after the handler | 4 |
| **migration** | a versioned, ordered change to a database schema | 5 |
| **MinIO** | S3-compatible object storage you run yourself | 8 |
| **module resolution** | how the runtime turns an import specifier into a file | 1, 3 |
| **monorepo** | one repository holding several packages that release together | 4 |
| **multi-AZ** | a standby database in a second availability zone, promoted automatically on failure | 8 |
| **multi-stage build** | compiling in one Docker stage and copying only the result into a clean one | 8 |
| **mutation testing** | breaking the code on purpose to find tests that never fail | 9 |
