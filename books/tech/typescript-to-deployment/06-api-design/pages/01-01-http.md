# Module 1 - HTTP, properly

## The protocol everything sits on

- Every framework in this book is a wrapper over one thing: a text request goes out, a text response comes back
- Knowing that layer is what separates guessing at a bug from reading the answer off the wire
- HTTP is **stateless**. Each request carries everything needed to serve it, and the server remembers nothing between them
- That is why authentication is a header on every request rather than something established once
- It is also why HTTP scales. Any instance can answer any request, so a load balancer can send traffic anywhere
- A request is a **method**, a **path**, **headers**, and optionally a **body**
- A response is a **status code**, **headers**, and optionally a **body**
- Everything else, REST included, is a convention layered on those six things

```http
POST /api/v1/orders HTTP/1.1
Host: api.example.com
Content-Type: application/json
Authorization: Bearer eyJhbGciOi...
Idempotency-Key: 8f14e45f

{"sellerId":"s1","totalPaise":50000}
```

```http
HTTP/1.1 201 Created
Content-Type: application/json
Location: /api/v1/orders/o_842

{"data":{"id":"o_842","status":"pending"}}
```
