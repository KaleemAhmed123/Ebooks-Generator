## The twelve things worth remembering

### 1. The bottleneck moved to review

- Generation got fast. Delivery did not follow unless the review and the gates changed too

### 2. You own every line you merge

- Generated is fine. Unread is not. "The agent wrote it" is not an answer at 3am

### 3. A check it can run is worth more than any prompt

- A failing test turns one guess into a loop that converges. Never delegate what you cannot verify

### 4. Point at an example in your repository

- One sentence transfers every convention. It beats any amount of describing them

### 5. Say what not to touch

- Scope creep is the most common defect. An explicit exclusion list is the only reliable defence

### 6. Review the plan, not just the diff

- Two sentences at the plan stage replaces a large rejected change

### 7. Enforce it with a rule, not with prose

- A lint rule teaches every agent and every human, forever. A line in a rules file is advisory

### 8. Break the implementation to check the test

- Thirty seconds, and the only reliable way to know a generated test is real

### 9. A human approves every new dependency

- Hallucinated package names are repeatable, and attackers have registered them
