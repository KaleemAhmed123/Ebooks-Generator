### What makes it work

- **Requirements are numbered**, so a review comment and a task can reference one
- **"Done when" is testable**, not "payouts work better"
- **Open questions are listed with a proposed answer**, so the reader decides rather than writes
- **The problem section carries the stakes.** "40 times a week" and "pays twice" tell an agent which requirement matters most

### Length

- **One page.** A spec longer than the code it produces is a sign the change should be split
