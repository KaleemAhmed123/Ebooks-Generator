## The `this` keyword

- `this` is decided by **how a function is called**, not where it was written
- Four rules, checked in this order

### 1. `new`

```js
function Seller(name) { this.name = name }
const s = new Seller("kaleem")
s.name   // "kaleem"
```

- `this` is the new object

### 2. Called on an object

```js
const shop = {
  name: "kaleem",
  greet() { return this.name },
}
shop.greet()   // "kaleem"
```

- `this` is whatever is left of the dot

### 3. `call`, `apply` or `bind`

```js
shop.greet.call({ name: "rabiya" })   // "rabiya"
```

- `this` is whatever you passed

### 4. Plain call

```js
const fn = shop.greet
fn()   // undefined in strict mode
```

- `this` is `undefined` in strict mode, or the global object without it
- This is the bug behind almost every "cannot read property of undefined" in a callback
