### Lifecycle policies, because storage is billed

```json
{
  "rules": [{
    "rulePriority": 1,
    "description": "keep the last 30 images",
    "selection": { "tagStatus": "any", "countType": "imageCountMoreThan", "countNumber": 30 },
    "action": { "type": "expire" }
  }]
}
```

```bash
aws ecr put-lifecycle-policy --repository-name orders-api --lifecycle-policy-text file://lifecycle.json
```

- **Keep enough images to roll back several deploys.** Thirty is a reasonable default; five is not

### Pulling from a private subnet

- ECR pulls go over the internet by default, which means through the NAT gateway and onto the bill
- **Interface endpoints for `ecr.api` and `ecr.dkr`, plus the S3 gateway endpoint**, keep image pulls inside the VPC. ECR stores layers in S3, which is why all three are needed
