### The workflow side

```yaml
permissions:
  id-token: write             # required to request the OIDC token
  contents: read

steps:
  - uses: aws-actions/configure-aws-credentials@v6
    with:
      role-to-assume: arn:aws:iam::123456789012:role/github-deploy
      aws-region: ap-south-1
```

- Every AWS command after that step uses a credential valid for an hour

### The condition is the security boundary

- **`sub` must name the repository and the ref.** A trust policy matching `repo:acme/*` lets any repository in the organization assume the role
- **A wildcard on `sub` with no repository at all lets any GitHub repository on earth assume it.** That mistake has emptied accounts
- Use `repo:acme/orders-api:environment:production` to bind the role to a protected environment, which adds the approval gate to the credential itself
