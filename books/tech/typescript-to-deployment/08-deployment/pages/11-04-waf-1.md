## WAF and Shield

- A **web application firewall** inspects requests before they reach your service and blocks the ones matching a rule
- It is a layer, not a fix. It stops opportunistic scanning and known-bad patterns, and it does not make a vulnerable application safe

```bash
aws wafv2 create-web-acl --name orders-waf --scope REGIONAL \
  --default-action Allow={} \
  --visibility-config 'SampledRequestsEnabled=true,CloudWatchMetricsEnabled=true,MetricName=orders' \
  --rules file://rules.json

aws wafv2 associate-web-acl --web-acl-arn <arn> --resource-arn <alb-arn>
```

### The rules worth having on day one

| Rule group | Blocks |
|---|---|
| `AWSManagedRulesCommonRuleSet` | broad injection and traversal patterns |
| `AWSManagedRulesKnownBadInputsRuleSet` | known exploit payloads |
| `AWSManagedRulesAmazonIpReputationList` | addresses with a bad history |
| `AWSManagedRulesBotControlRuleSet` | scrapers and automated traffic. Billed extra |
| a **rate-based rule** | one address making thousands of requests |

```json
{ "Name": "rate-limit", "Priority": 10,
  "Statement": { "RateBasedStatement": { "Limit": 2000, "AggregateKeyType": "IP" } },
  "Action": { "Block": {} } }
```
