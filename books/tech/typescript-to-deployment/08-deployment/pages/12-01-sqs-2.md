### The model, and how it differs from RabbitMQ

- A consumer **receives** a message, which becomes invisible to others for the **visibility timeout**, then **deletes** it when done
- **Not deleting is how a message is retried.** There is no negative acknowledgement; the timeout expires and it reappears
- **`VisibilityTimeout` must exceed the longest processing time**, or the message is delivered again while still being worked on
- **Delivery is at-least-once.** A message can arrive twice, so handlers must be idempotent, as Booklet 6 describes

```ts
const { Messages } = await sqs.send(new ReceiveMessageCommand({
  QueueUrl: url, MaxNumberOfMessages: 10, WaitTimeSeconds: 20,
}))

for (const m of Messages ?? []) {
  await handle(JSON.parse(m.Body))
  await sqs.send(new DeleteMessageCommand({ QueueUrl: url, ReceiptHandle: m.ReceiptHandle }))
}
```

- **`WaitTimeSeconds: 20` is long polling and is not the default.** Without it you pay for empty receives in a tight loop

### Standard against FIFO

| | Standard | FIFO |
|---|---|---|
| Order | best effort | strict, per message group |
| Duplicates | possible | deduplicated within 5 minutes |
| Throughput | effectively unlimited | thousands per second |

- **Use standard unless order is a requirement.** A `MessageGroupId` on FIFO serializes everything sharing it, which is usually what you want per customer
