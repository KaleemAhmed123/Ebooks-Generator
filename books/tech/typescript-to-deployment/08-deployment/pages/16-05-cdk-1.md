## CDK and CloudFormation

- **CDK is TypeScript that generates CloudFormation.** You write classes; it emits a template and deploys it
- The appeal is real: loops, types, shared constructs, and the same language as the application

```bash
npm i -g aws-cdk
cdk init app --language typescript
```

```ts
import { Stack, Duration } from "aws-cdk-lib"
import * as ecs from "aws-cdk-lib/aws-ecs"
import * as patterns from "aws-cdk-lib/aws-ecs-patterns"

export class OrdersStack extends Stack {
  constructor(scope: Construct, id: string, props?: StackProps) {
    super(scope, id, props)

    const cluster = new ecs.Cluster(this, "Cluster", { vpc })

    new patterns.ApplicationLoadBalancedFargateService(this, "Api", {
      cluster,
      desiredCount: 2,
      cpu: 512,
      memoryLimitMiB: 1024,
      taskImageOptions: {
        image: ecs.ContainerImage.fromEcrRepository(repo, process.env.GIT_SHA!),
        containerPort: 3000,
      },
      healthCheckGracePeriod: Duration.seconds(60),
    })
  }
}
```

- **That one construct creates the VPC wiring, the ALB, the listener, the target group, the task definition, the service and the log group.** It is a large amount of correct default configuration
