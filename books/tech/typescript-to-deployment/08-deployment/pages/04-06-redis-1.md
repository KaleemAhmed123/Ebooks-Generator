## Redis and Valkey

- **Valkey is the open source fork of Redis**, protocol-identical and a drop-in replacement. Either is fine; Valkey avoids the license question entirely
- The configuration depends entirely on **what you are using it for**, and using one instance for two purposes is the common mistake

| Use | Persistence | `maxmemory-policy` | Losing it means |
|---|---|---|---|
| **cache** | none needed | `allkeys-lru` | a slow request |
| **sessions** | AOF | `noeviction` | everyone logged out |
| **job queue** (BullMQ) | **AOF** | **`noeviction`** | **lost jobs** |
| rate limiting | none | `allkeys-lru` | limits reset |

```yaml
  redis:
    image: redis:8-alpine
    restart: unless-stopped
    command:
      - redis-server
      - --appendonly=yes
      - --appendfsync=everysec
      - --maxmemory=768mb
      - --maxmemory-policy=noeviction
      - --requirepass=${REDIS_PASSWORD:?}
      - --save=900 1
    volumes: ["./data/redis:/data"]
    healthcheck:
      test: ["CMD", "redis-cli", "--no-auth-warning", "-a", "${REDIS_PASSWORD}", "ping"]
      interval: 10s
    deploy: { resources: { limits: { memory: 1G } } }
```

### The rule that loses jobs

- **`allkeys-lru` on a queue node deletes jobs when memory fills.** No error, no log line, the job is simply gone
- **`noeviction` returns an error to the writer instead**, which is a visible failure you can alert on
- **Run two instances if you need both behaviors.** They cost almost nothing
