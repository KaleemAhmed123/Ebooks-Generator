## OCR

- A scanned invoice, a photographed receipt or an old contract is an image. There is no text to extract
- **Optical character recognition** turns those pixels into characters, and it is the entry point for a large share of real document work
- The choice now is between a classical engine and a vision model, and they fail in different ways

| Approach | Good at | Weak at |
|---|---|---|
| **Tesseract**, self-hosted | clean scans, no per-page cost | layout, tables, handwriting |
| **Cloud OCR** (Textract, Document AI) | forms, tables, key-value pairs | cost, another vendor |
| **A vision model** | messy layouts, reasoning about the page | hallucinating a plausible number |

```ts
const message = await client.messages.create({
  model: "claude-opus-5",
  max_tokens: 1024,
  messages: [{ role: "user", content: [
    { type: "document",
      source: { type: "base64", media_type: "application/pdf", data: pdfBase64 } },
    { type: "text", text: "Extract invoice number, date and total." },
  ]}],
  output_config: { format: zodOutputFormat(Invoice) },
})
```

- A vision model reads layout, so it handles a table that classical OCR turns into a wall of numbers
- Pairing it with structured output turns a scanned page into a typed object in one call

### The rule that matters most

- **A vision model can invent a digit and give no warning.** Classical OCR produces obvious garbage; a model produces a plausible wrong total
- For money, dates and identifiers, **validate what comes back**: checksums, totals that must add up, dates in range, and a human review path above a threshold
