## What it costs

- Billing is per token, and **input and output are priced separately**, with output several times more expensive
- Nothing else in a backend has this shape. A single endpoint can cost fractions of a rupee or hundreds, depending on what the caller typed
- That is why cost control is a design concern here rather than a finance one

### Where the money actually goes

- **The chat that grows.** Turn twenty resends turns one to nineteen, so the same conversation costs more each message
- **The document stuffed into every request.** A 50,000 token policy file sent on every call, when caching or retrieval would have avoided it
- **The agent that loops.** Ten tool-calling steps is ten full requests, each carrying everything before it
- **The retry.** A failed parse retried three times is four times the cost of one call

```ts
console.log(response.usage)
// { input_tokens: 2140, output_tokens: 318,

```

### The four levers, in the order worth pulling them

| Lever | Typical saving |
|---|---|
| a smaller model for the easy calls | very large |
| prompt caching on the fixed prefix | up to 90 percent of input cost |
| trimming or summarizing history | large on long chats |
| shorter outputs, tighter `max_tokens` | moderate |

- **Log `usage` on every call, with the user or tenant id attached.** Without that record there is no way to find which feature is expensive
