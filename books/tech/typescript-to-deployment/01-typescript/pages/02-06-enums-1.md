## Enums, and why a `const` object often wins

- Some values come from a fixed set. An order is pending, paid or shipped, and nothing else
- Using plain strings works until someone writes `"shiped"` and the compiler has no reason to object
- An **enum** names that set so the compiler can check membership
- TypeScript's `enum` is unusual, because unlike almost everything else in the language it **emits real JavaScript**
- That makes it non-erasable, which is why Node's type stripping refuses it and why a plain object is now usually the better answer

### The enum

```ts
enum Status {
  Open = "open",
  Closed = "closed",
}

const s: Status = Status.Open
```

### Why teams are moving away from it

- An `enum` **emits real JavaScript**. It is not just a type
- That means it cannot be erased, so Node's type stripping refuses it
- Numeric enums are worse: any number is assignable to them

```ts
enum Level { Low, High }
const l: Level = 42     // no error. 42 is not a Level
```
